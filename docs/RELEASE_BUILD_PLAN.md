# خطة تصغير APK والانتقال إلى بناء Release

> **الحالة (2026-10-27):** ✅ **تم القياس فعليًا — الهدف تحقّق.**
> بناء release لأول مرة (Run #40509037207، run artifact `apk-release`).

## 1) لماذا حجم debug كبير؟

| السبب | الأثر التقريبي |
|---|---|
| APK debug غير مُحسَّن (لا R8/Shrink، رموز كاملة) | الأكبر — عادة ضعف حجم release تقريبًا |
| `flutter build apk` بلا `--split-per-abi` يحمل مكتبات **كل** المعماريات | ~1.7× (ثلاث نسخ من المكتبات الأصلية) |
| حزم Firebase تضيف مكتبات أصلية كبيرة | عشرة ميغابايتات أو أكثر في debug |
| خط Cairo مضمَّن (3 أوزان، ~164 ك.ب لكل وزن) | ~0.5 م.ب — مقبول ومقصود |

### الأرقام المقاسة

| البناء | arm64 | armv7 | ملاحظات |
|---|---|---|---|
| debug (سابقًا) | **86.6 MiB** | 62.6 MiB | 152 MiB قبل `--split-per-abi` |
| **release (مقاس 2026-10-27)** | **18.5 MiB** | **16.1 MiB** | توقيع debug (الأسرار غير مضافة)، R8 يعمل |
| التخفيض | **−78.6%** | −74.3% | — |

**النتيجة:** نسخة release تقع داخل نطاق 15–20 م.ب المطلوب، وarm64 (الأكثر
انتشارًا) 18.5 MiB — أي أن تنزيل نسخة تجريبية صار ممكنًا على باقة محدودة.

## 2) خطة التحويل (بالترتيب)

### المرحلة أ — ما هو جاهز الآن ✅
1. **`--split-per-abi` + `--target-platform android-arm64,android-arm`**
   (منفَّذ في الـworkflow).
2. **بناء عند الطلب فقط** (منفَّذ): لا استهلاك دقائق/تخزين في كل دفعة.

### المرحلة ب — أُنجزت في 2026-10-27 ✅
3. **`flutter build apk --release --split-per-abi`** — نُفِّذ، والنتيجة 18.5 MiB.
4. **قياس الحجم** — مسجَّل أعلاه، والهدف تحقّق بلا حاجة لخطوات إضافية.

### المرحلة ج — إن تغيّر الحجم لاحقًا (احتياط)
5. إن تجاوز الحجم الهدف بعد إضافة ميزات (Firestore يضيف مكتبات أصلية):
   تُطبَّق الخطوات التالية بالترتيب:
   - التأكد من تفعيل `isMinifyEnabled`/`isShrinkResources` في
     `android/app/build.gradle(.kts)` (Flutter يفعّلها في release افتراضيًا،
     لكن يجب التحقق من ملف المشروع المولَّد).
   - مراجعة `firebase_auth`/`cloud_firestore`: لا يمكن حذفهما (مطلوبان)،
     لكن يمكن التحقق من عدم سحب مزوّدات غير مستخدمة.
   - إبقاء `arm64` فقط للنسخ التجريبية الداخلية (يوفّر نسخة arm كاملة).
6. **App Bundle بدل APK للتوزيع النهائي** (Google Play): `--split-per-abi` غير
   مطلوب مع AAB؛ Play يسلّم للمستخدم مكتبة معماريته فقط. هذا هو المسار الرسمي.

### المرحلة د — إن بقي الحجم أكبر من الهدف
7. **تقليل أوزان الخط** (Cairo Regular + Bold فقط بدل ثلاثة) — توفير ~0.2 م.ب
   فقط، لذا هي آخر خيار لأنها تُضعف التسلسل البصري.
8. **مراجعة `flutter build apk --analyze-size`** لمعرفة أكبر المساهمين قبل أي
   قرار آخر (الأداة تُنتج تقريرًا بحسب الحزمة/المكتبة).

| الوضع | توقّعي | **الواقع المقاس** |
|---|---|---|

الأخذ بالقياس لا بالتقدير كان صحيحًا.

> ⚠️ **الحجم ليس دليل عمل:** لم يُثبَّت هذا الـrelease على جهاز. R8 قد يحذف
> شيئًا يحتاجه Firebase في وقت التشغيل؛ التحقق يحتاج تثبيتًا فعليًا وتسجيل
> دخول حقيقي (مستحيل الآن بلا مشروع Firebase).

## 4) قيود أمنية عند الانتقال إلى Release (مهمة)

1. **مفتاح توقيع الإصدار** — أُنشئ تجريبيًا في `2026-10-27` وهو **خارج Git**،
   ويُحقن وقت البناء عند وجود أسرار CI (تفاصيل ومخاطر: `docs/SIGNING.md`).
   إن غابت الأسرار يُبنى الإصدار بتوقيع debug — صالح للتجربة الداخلية فقط.
2. **Google Sign-In في Release** يحتاج بصمة SHA-1 **لمفتاح الإصدار** مضافة في
   Firebase Console (بصمة debug لا تكفي).
3. **إزالة أي تسجيل تشخيصي** حساس قبل التوزيع العام (لا توجد أسرار مسجّلة الآن).

## 5) ما يحتاجه التنفيذ من صاحب المشروع

- قرار: هل نُنشئ مفتاح توقيع تجريبي الآن أم نبني release موقّعًا بـdebug key
  للتجربة الداخلية فقط؟
- تشغيل البناء من **Actions ← Run workflow ← build_mode = release**.
- قياس الحجم وإرساله، ثم تحديث هذا الملف بالأرقام الحقيقية.
